En PostgreSQL, cuando trabajas con tipos de datos de fecha y hora (`timestamp`), la resta directa entre dos columnas de tipo `timestamp` (o `timestamp without time zone`) **no** produce directamente un tipo `time` ni un `interval` estricto que pueda asignarse de forma directa sin una función de conversión, ya que la resta de dos timestamps devuelve un tipo de datos **`interval`**.

Dado que en tu script la columna `tiempo_reserva` fue definida como de tipo `time without time zone`, tenemos dos detalles importantes a considerar:

1. Si usas `GENERATED ALWAYS AS`, la expresión debe coincidir exactamente con el tipo de dato de la columna.
2. Un tipo `time` almacena una hora del día (ej. `14:30:00`), mientras que una diferencia de tiempo (como "2 horas y media") se representa correctamente en PostgreSQL con el tipo **`interval`** o convirtiéndola explícitamente si se requiere `time`.

### Opción Recomendada: Cambiar `tiempo_reserva` a tipo `INTERVAL`

Lo técnicamente correcto para representar una duración o diferencia de tiempo es usar `interval`. De esta manera, la columna generada calculará la diferencia exacta entre la fecha-hora de fin y la de inicio sin pérdida de datos.

Aquí tienes el script adaptado e integrado utilizando `GENERATED ALWAYS AS (...) STORED` con el tipo `interval`:

```sql
CREATE TABLE IF NOT EXISTS practica02.reservas
(
    id serial,
    espacio_id integer,
    persona_id integer,
    evento text,
    inicio_fecha_hora timestamp without time zone DEFAULT NOW(),
    fin_fecha_hora timestamp without time zone DEFAULT NOW(),
    estatus practica02.reserva_estatus,
    -- Cambiamos a INTERVAL para almacenar correctamente la diferencia de tiempo
    tiempo_reserva interval GENERATED ALWAYS AS (fin_fecha_hora - inicio_fecha_hora) STORED,
    PRIMARY KEY (id)
);

```

---

### ¿Qué pasa si necesitas obligatoriamente que sea de tipo `TIME`?

Si por diseño de tu esquema la columna `tiempo_reserva` **debe** ser estrictamente de tipo `time without time zone`, PostgreSQL requiere que hagas un `CAST` (conversión) explícito del resultado del intervalo al tipo `time`:

```sql
CREATE TABLE IF NOT EXISTS practica02.reservas
(
    id serial,
    espacio_id integer,
    persona_id integer,
    evento text,
    inicio_fecha_hora timestamp without time zone DEFAULT NOW(),
    fin_fecha_hora timestamp without time zone DEFAULT NOW(),
    estatus practica02.reserva_estatus,
    -- Forzamos la conversión del intervalo resultante a tipo TIME
    tiempo_reserva time without time zone GENERATED ALWAYS AS (CAST((fin_fecha_hora - inicio_fecha_hora) AS time)) STORED,
    PRIMARY KEY (id)
);

```

### ¿Cómo funcionaría en un `INSERT`?

Al tratarse de una columna generada automáticamente, al insertar registros **no debes incluir** `tiempo_reserva` en la sentencia. El motor de PostgreSQL hará el cálculo por ti:

```sql
INSERT INTO practica02.reservas (espacio_id, persona_id, evento, inicio_fecha_hora, fin_fecha_hora, estatus)
VALUES (
    1, 
    1, 
    'Reunión de planificación', 
    '2026-06-10 08:00:00', 
    '2026-06-10 10:30:00', 
    'CONFIRMADA'
);

```

Al consultar la tabla, la columna `tiempo_reserva` mostrará automáticamente el resultado del cálculo (`02:30:00`).

FIN DE LA EJECUCIÓN

**SSH** (Secure Shell o Intérprete Seguro) es un protocolo de red criptográfico que permite a los usuarios —especialmente administradores de sistemas y desarrolladores— conectarse y gestionar computadoras o servidores remotos de forma totalmente segura y cifrada a través de una red no segura (como Internet).

---

### **Funciones Clave**

* **Acceso remoto a terminal:** Permite abrir una línea de comandos interactiva en un servidor remoto para ejecutar instrucciones como si estuvieras frente a él.
* **Autenticación robusta:** Utiliza contraseñas o, de forma más segura, pares de claves criptográficas (clave pública y clave privada) para validar la identidad sin exponer credenciales.
* **Transferencia de archivos:** Sirve de base para protocolos seguros de intercambio de datos como SFTP (Secure File Transfer Protocol) y SCP.
* **Túneles y redireccionamiento:** Permite redirigir puertos y cifrar el tráfico de otras aplicaciones (como bases de datos o conexiones web) de extremo a extremo.
